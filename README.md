# RosMetrics — versi Supabase

Platform analitik kesehatan organisasi UMKM (OH-Index, 6 faktor).
Project ini sudah dikonversi dari **PHP + MySQL (InfinityFree)** menjadi **Supabase (PostgreSQL + Edge Functions)**.

> Supabase tidak menjalankan PHP, jadi `api.php` ditulis ulang sebagai **Edge Function TypeScript**.
> Kontrak API (nama action, request, response) **sama persis**, sehingga kode frontend hampir tidak berubah.

## Struktur

```
rosmetrics-supabase/
├── supabase/
│   ├── config.toml                                  # verify_jwt=false untuk function `api`
│   ├── migrations/20260101000000_init_nexaumkm.sql  # skema PostgreSQL (pengganti database.sql)
│   └── functions/api/index.ts                       # REST API (pengganti api.php + validator.php + db.php)
├── frontend/                                        # situs statis (HTML/CSS/JS)
│   ├── index.html, data_asli.csv, Panduan_*.pdf
│   ├── css/  js/  (js/config.js = tempat mengisi URL API)
├── .env.example                                     # daftar secret yang dibutuhkan
├── stress-test.js                                   # k6, sudah diarahkan ke ?action=health
└── pdfgen.js, package.json
```

## Apa yang berubah

| Sebelumnya (MySQL/PHP)                         | Sekarang (Supabase)                                              |
|------------------------------------------------|------------------------------------------------------------------|
| `INT UNSIGNED AUTO_INCREMENT`                  | `integer generated by default as identity`                       |
| `ENUM(...)`                                    | `CREATE TYPE ... AS ENUM` (`user_role`, `submission_status`, …)  |
| `TINYINT(1)` (`is_active`, `validation_pass`)  | `boolean`                                                        |
| `DATETIME ... ON UPDATE CURRENT_TIMESTAMP`     | `timestamptz` + trigger `set_updated_at()`                       |
| `BIGINT UNSIGNED` (`omzet`)                    | `bigint` + `CHECK (omzet >= 0)`                                  |
| `INSERT IGNORE`                                | `ON CONFLICT DO NOTHING`                                         |
| `ON DUPLICATE KEY UPDATE`                      | `ON CONFLICT (submission_id, question_id) DO UPDATE`             |
| `LIKE` (case-insensitive karena collation)     | `ILIKE`                                                          |
| `SUM(kolom = 1)`                               | `COUNT(*) FILTER (WHERE ...)`                                    |
| `lastInsertId()`                               | `RETURNING id`                                                   |
| `"owner"` (string kutip ganda)                 | `'owner'` (kutip tunggal)                                        |
| PDO + `password_hash` bcrypt                   | `postgres.js` + `bcryptjs` (hash lama `$2y$` tetap bisa dipakai) |
| JWT HS256 native PHP                           | JWT HS256 Web Crypto (token format sama)                         |
| `.htaccess`, `test.php`                        | CORS di function; `?action=health` menggantikan `test.php`       |

**Keamanan database:** semua tabel memakai Row Level Security tanpa policy dan hak `anon`/`authenticated` dicabut,
jadi tabel tidak bisa dibaca langsung dari browser. Semua akses lewat Edge Function.

## Langkah deploy

Prasyarat: akun Supabase, [Supabase CLI](https://supabase.com/docs/guides/cli), dan project Supabase baru.

```bash
# 1. Login & hubungkan ke project
supabase login
supabase link --project-ref <PROJECT_REF>      # Reference ID: Dashboard > Project Settings > General

# 2. Buat tabel (atau paste isi file migrasi ke Dashboard > SQL Editor > Run)
supabase db push

# 3. Set secret
supabase secrets set JWT_SECRET="$(openssl rand -hex 32)" \
                     CORS_ORIGIN="https://domain-frontend-kamu.com"

# 4. Deploy API
supabase functions deploy api --no-verify-jwt

# 5. Cek
curl "https://<PROJECT_REF>.supabase.co/functions/v1/api?action=health"
# -> {"success":true,"message":"","data":{"status":"ok","db":true}}
```

6. Edit **`frontend/js/config.js`**, ganti `YOUR_PROJECT_REF` dengan Reference ID kamu.
7. Upload folder `frontend/` ke hosting statis (Vercel, Netlify, Cloudflare Pages, GitHub Pages, dsb.).
   Supabase sendiri tidak menyediakan hosting situs statis. Setelah URL frontend jadi, isi `CORS_ORIGIN`
   dengan URL itu (jalankan ulang `supabase secrets set CORS_ORIGIN=...`; tidak perlu deploy ulang function).

## Memindahkan data lama dari MySQL (opsional)

Lewati bagian ini jika mulai dari database kosong.

1. Di phpMyAdmin, export tiap tabel sebagai **CSV**: `users`, `submissions`, `answers`, `validation_log`
   (`factor_definitions` dan `question_definitions` sudah terisi oleh migrasi).
2. Di Supabase: **Table Editor > pilih tabel > Insert > Import data from CSV**, berurutan
   `users` → `submissions` → `answers` → `validation_log`.
   Nilai `1`/`0` pada kolom boolean dan teks enum diterima apa adanya.
3. Setelah import, sinkronkan counter ID di **SQL Editor**:

```sql
select setval(pg_get_serial_sequence('public.users','id'),          coalesce(max(id),1)) from public.users;
select setval(pg_get_serial_sequence('public.submissions','id'),    coalesce(max(id),1)) from public.submissions;
select setval(pg_get_serial_sequence('public.answers','id'),        coalesce(max(id),1)) from public.answers;
select setval(pg_get_serial_sequence('public.validation_log','id'), coalesce(max(id),1)) from public.validation_log;
```

Password user lama tetap berlaku (hash bcrypt `$2y$` kompatibel). Karena `JWT_SECRET` baru, semua user cukup login ulang.

## Catatan keamanan penting

- File `backend/php/config.php` versi lama berisi **JWT secret yang di-hardcode** dan file `env` memuat
  hostname + username database InfinityFree. Jika repo itu pernah publik, anggap keduanya bocor:
  jangan dipakai lagi, dan ganti password database lama.
- Jangan pernah menaruh `service_role` key atau `JWT_SECRET` di folder `frontend/`.
- Edge Function menolak berjalan bila `JWT_SECRET` belum diset atau kurang dari 32 karakter.

## Perbedaan perilaku kecil dibanding versi PHP

- **Password** kini divalidasi juga di server (min. 8 karakter, sama dengan aturan di form). Versi PHP hanya memeriksa di browser.
- **Pencarian** `umkm_list`: frontend mengirim `q`, versi PHP membaca `search` (sehingga pencarian tidak pernah bekerja). Sekarang keduanya didukung.
- **Angka** (skor, omzet, jumlah) dikirim sebagai number JSON, bukan string seperti `DECIMAL` MySQL.
- **Jawaban** harus bilangan bulat; nilai seperti `3.7` kini ditolak (`OUT_OF_RANGE`) alih-alih dibulatkan diam-diam.
- Tanggal `submitted_at` tetap dikirim sebagai `YYYY-MM-DD HH:MM:SS` dalam WIB.
- `limit` pada `umkm_list` dibatasi `PAGE_LIMIT_MAX` (default 100), sama seperti versi PHP.
- Endpoint baru: `?action=me` (dipanggil `DashboardAPI.getMe()` di frontend tetapi tidak ada di versi PHP) dan `?action=health`.

## Tes cepat via curl

```bash
API=https://<PROJECT_REF>.supabase.co/functions/v1/api

curl -X POST "$API?action=register" -H 'Content-Type: application/json' \
  -d '{"role":"owner","umkm_name":"Warung Contoh","email":"contoh@mail.com","password":"rahasia123","lokasi":"Jakarta","sektor":"Kuliner","omzet":5000000}'

curl -X POST "$API?action=login" -H 'Content-Type: application/json' \
  -d '{"email":"contoh@mail.com","password":"rahasia123","role":"owner"}'

curl "$API?action=dashboard" -H "Authorization: Bearer <TOKEN>"
```
